# 자율주행 데이터 취득 네비게이션 — Ver.3 (TMAP)

Ver.1(main)의 **기본 기능만** 남기고, 지도와 경로 생성을 **전부 TMAP API로 교체한** 버전입니다.
Ver.2(`Thanks-to-SOOHEON00`)의 확장 기능은 이 브랜치 위에 차례로 얹어 갈 예정입니다.

| 버전 | 브랜치 | 지도 | 경로 |
|------|--------|------|------|
| Ver.1 | `main` | Leaflet + OpenStreetMap | OSRM |
| Ver.2 | `Thanks-to-SOOHEON00` | Leaflet + OpenStreetMap | OSRM + HD 도로 데이터 |
| **Ver.3** | **이 브랜치** | **TMAP Vector Map (JS SDK v2)** | **TMAP 자동차 경로안내 API** |

Ver.3는 Ver.1 기본 기능에서 출발해 Ver.2 기능을 하나씩 옮겨오는 중입니다.
현재 `routes.json` 경로 원본과 섹터(자유주행 구역)까지 반영되어 있습니다.

## 기술 구성

| 구분 | 사용 기술 |
|------|-----------|
| 화면 | HTML5, CSS3, JavaScript (단일 파일) |
| 지도 | TMAP JS SDK v2 (`Tmapv2`) |
| 경로 | TMAP 자동차 경로안내 API (`POST /tmap/routes`) |
| 역지오코딩 | TMAP 리버스 지오코딩 API |
| GPS | Browser Geolocation API |
| 음성 안내 | Web Speech API (한국어 TTS) |
| 엑셀 생성 | SheetJS (XLSX) / CSV 폴백 |
| 데이터 저장 | localStorage · sessionStorage |
| 오프라인 | Service Worker |
| 앱 형태 | PWA |

## 시작하기

1. [openapi.sk.com](https://openapi.sk.com) 에서 앱을 등록하고 `appKey`를 발급받습니다.
   상품은 **TMAP** 하나만 등록하면 됩니다 (지도·자동차 경로안내·리버스 지오코딩이 모두 포함).
   TMAP TMS, TMAP 대중교통은 필요 없습니다.
2. GitHub Pages 등으로 배포한 뒤, SK open API 콘솔에 **배포 도메인을 등록**합니다.
   (등록하지 않으면 SDK 로드와 API 호출이 모두 거부됩니다.)
3. `index.html` 상단 **28번째 줄**의 `DEFAULT_APPKEY`에 키를 넣습니다.

   ```js
   var DEFAULT_APPKEY = '여기에_발급받은_키';
   ```

   여러 사람에게 배포할 때는 이 방식을 쓰세요. 사용자가 키를 입력할 필요가 없습니다.
   비워두면 앱 첫 화면에서 키를 직접 입력받습니다.
4. 차량과 이름을 선택하고 입장 → 지역·시나리오 선택 → **▶ 시작**.

### 키가 정해지는 순서

`?appKey=...` (URL) → `DEFAULT_APPKEY` (파일) → 사용자가 입력해 저장한 키

배포본에 심은 키를 저장값보다 앞에 둡니다. 기기에 남아 있던 옛 키 때문에
지도가 안 뜨는 상황을 막기 위해서입니다. `DEFAULT_APPKEY`가 채워져 있으면
설정 메뉴의 **🔑 appKey 변경** 항목은 자동으로 숨겨집니다.

> ⚠️ appKey는 브라우저에서 그대로 노출됩니다. 숨길 수 없는 구조이므로,
> SK open API 콘솔의 **도메인 제한**으로 보호하세요. 등록한 도메인 밖에서는
> 키를 복사해가도 쓸 수 없습니다.
>
> TMAP JS SDK는 내부적으로 `document.write()`를 쓰기 때문에 반드시 문서 파싱 시점에
> 동기 로드해야 합니다. 그래서 `<head>`의 인라인 스크립트가 저장된 키를 읽어
> SDK 태그를 직접 써 넣고, 키를 새로 입력하면 페이지를 새로고침합니다.
> 이 부분을 동적 `appendChild` 방식으로 바꾸면 SDK 초기화가 실패합니다.

`file://`로 직접 열면 동작하지 않습니다. origin이 `null`이라 appKey 검증에 걸리고
Geolocation도 차단됩니다. 로컬 확인은 `python3 -m http.server 8000` 후
`http://localhost:8000`으로 접속하고, 콘솔에 `localhost:8000`도 등록해 두세요.

## 구현된 기능 (Ver.1 기본 세트)

- **로그인** — 차량(토레스 1–4호차) · 이름 선택, 세션 유지, 헤더 배지 표시
- **지역·시나리오** — 강남 / 판교 / 시흥 × ㄹ자 그리드 · M자 그리드 · 링 (총 87개 구간)
- **경로** — TMAP 자동차 경로안내로 실제 도로 경로 생성, 지나간 구간 회색 / 남은 구간 파랑
- **턴바이턴** — 지도 위 오버레이(다음 회전·거리·도로명) + 전체 경로 안내 목록
- **음성 안내** — 500 m / 200 m / 50 m 사전 안내, 출발·이탈·도착·휴식, 🔊 음소거 토글
- **GPS 추적** — 실시간 위치·진행 방향, 자동 추적(수동 조작 시 10초 일시정지), 수신 상태 배지
  - **룩어헤드** — 지도 중심을 차량보다 진행 방향 앞쪽(화면 세로 18%, 최대 140px)에 두어
    차가 화면 아래쪽에 오고 앞길이 더 보입니다. 실제 내비와 같은 배치입니다.
  - **주행 배율** — ▶ 시작하면 배율 17로 당깁니다. 구간이 바뀌면 다시 적용됩니다.
  - **방향 스무딩** — GPS heading이 튀어도 지도가 흔들리지 않도록 각도를 다듬습니다
    (359°↔1° 경계 처리 포함). 속도 0.5 m/s 미만이면 이전 방향을 유지해, 정차 중
    방향이 제멋대로 도는 것을 막습니다.
  - **🧭 헤딩업** — 진행 방향이 위로 오도록 지도를 돌립니다(기본 꺼짐).
    `#map_div`만 CSS로 회전시키므로 턴 안내 오버레이와 버튼은 함께 돌지 않습니다.
    회전으로 드러나는 모서리는 1.45배 확대로 덮는데, 그만큼 벡터 타일이 약간 흐려집니다.
    지도 위 지명도 함께 회전하므로 남쪽으로 달릴 때는 글자가 뒤집힙니다 — 이 방식의 한계입니다.
  - **🎯 버튼** — 내 위치로 즉시 복귀하고 따라가기를 재개합니다(한 번 더 누르면 해제).
    **🗺️ 전체 경로 보기**를 누르면 북쪽 고정으로 돌아갑니다.
  - 경로 수정 중에는 탭 위치를 가늠하기 어려워 회전이 자동으로 풀리고, 편집을 마치면 복원됩니다.
- **자동 진행** — 도착지 50 m 이내 접근 시 구간 완료 → 다음 구간으로 바로 이동
- **경로 이탈** — 100 m 초과가 3회 연속되면 경고
- **주행기록지** — Ver.2 v4.0.0 형식을 그대로 옮기되 기록 주기만 **30초 → 10초**로 바꿨습니다.

  로그인 직후부터 로그아웃까지, 주행 시작/정지와 무관하게 10초마다 GPS 스냅샷을 남깁니다.

  | 컬럼 | 설명 |
  |------|------|
  | 번호 / 날짜 / 시각 | 기록 순번과 시각 |
  | GPS위치 | 위도, 경도 (소수점 5자리) |
  | 도로종류 | 구간 `road` 키워드로 자동차전용 / 도심 분류 |
  | 날씨 | Open-Meteo 실측 — 강수량·운량 우선, 코드는 보조 (5분 캐시) |
  | 시간대 | 일출(5~7) / 주간(8~16) / 일몰(17~19) / 야간 |
  | 장소 | 강남 / 성남 / 시흥 |
  | 교통밀도 | **항상 빈칸** — 아래 참고 |
  | 차량속도(km/h) | GPS 실측 속도 |

  저장소는 **IndexedDB**입니다. 10초 주기면 하루 2,880건이 쌓이는데, localStorage는
  저장할 때마다 전체 배열을 다시 써서 기록이 늘수록 느려지고 용량 한도에도 닿습니다.

  ⚠️ **교통밀도는 채워지지 않습니다.** Ver.2는 ITS 도로 흐름 실측으로 판정하는데
  Ver.3에는 ITS 연동이 없습니다. 내 차 속도로 대체하면 신호 대기만 걸려도 '정체'로
  잘못 기록되므로, 틀린 값을 남기는 대신 빈칸(`—`)으로 둡니다. 필요하면 ITS 연동을
  따로 붙여야 합니다.
- **설정 내보내기/가져오기** — 주행 기록과 UI 상태를 JSON으로 이식
- **PWA** — 홈 화면 설치, 오프라인 앱 셸

## Ver.1 대비 달라진 점

- **경유점 기본 해제** — Ver.1/Ver.2의 `WAYPOINTS`는 OSRM을 네이버 경로에 맞추려고 넣은 것이라
  TMAP에 그대로 주면 오히려 경로가 꼬입니다. 실제로 경유점이 있는 73개 구간 중 **20개**에서
  경유점 순서가 진행 방향을 120도 넘게 되돌렸고, TMAP은 `passList`를 준 순서대로 반드시
  들르기 때문에 갔다가 되돌아오는 선이 그대로 그려졌습니다
  (`SH-L-BASE-04`는 직선 0.5km인데 경유점 경로가 7km).

  그래서 경유점은 **기본 꺼짐**이고, 설정 메뉴의 **📍 고정 경유점 사용**으로 켤 수 있습니다.
  켰을 때도 `sanitizeWaypoints()`가 되돌아가는 경유점을 자동으로 걸러냅니다
  (전 지역 되돌림 20건 → 0건, 경유점 127개 중 65개 유지).

- **순환 구간 주의** — 출발지와 도착지가 300 m 이내인 구간이 9개 있습니다
  (판교 `PG-M-BASE-08` 등, 시흥 링 시나리오). 이런 구간은 경유점이 없으면 경로가
  거의 생기지 않으므로, 앱이 경유점을 켜라고 안내합니다.

- **경유점 개수 제한** — TMAP 자동차 경로안내 API는 경유지를 최대 5개까지 받습니다.
  그보다 많으면 균등 간격으로 솎아서 전달합니다.
- **회전 안내 코드** — OSRM의 `maneuver.type/modifier` 대신 TMAP `turnType`을 사용합니다.
  `turnType` 코드표는 문서 버전마다 세부 값이 갈리는 부분이 있어, 확실한 코드만 표(`TURN_TYPE`)로 두고
  나머지는 TMAP이 함께 내려주는 한글 `description`에서 회전 방향을 읽어 보정합니다(`DESC_HINTS`).
  실주행에서 어긋나는 코드가 보이면 이 두 곳만 고치면 됩니다.
- **역지오코딩** — Nominatim 다단계 재시도 → TMAP 리버스 지오코딩 1회 호출로 단순화
- **거리·시간 표기** — 총 거리·예상 시간은 TMAP 응답값, 남은 거리는 경로 좌표 기준 진행률로 계산
- **타이머 제거** — Ver.1의 주행·휴식 타이머와 5분 경고는 넣지 않았습니다.
  구간 계획 시간(`time`)은 현재 구간 카드의 "계획 (분)"에만 표시됩니다.
- **경로선 순서** — `sort=index`로 요청하고, 응답 조각도 코드에서 한 번 더 index 순으로 정렬합니다.
  이 정렬이 빠지면 경로 조각이 뒤엉켜 같은 길이 여러 번 그려집니다.
- **핀 연결 제한** — 출발·도착 핀이 도로에서 150 m 넘게 떨어져 있으면 직선으로 잇지 않습니다.
  TMAP이 가까운 도로로 스냅한 경우까지 이으면 실제로 주행하지 않는 선이 생깁니다.

## Ver.2에서 가져온 기능

### routes.json — 경로 원본
저장소 루트의 `routes.json`이 있으면 내장 시나리오 위에 덮어씁니다.
구간·경유점·시나리오 이름·구역이 모두 여기서 나오므로, **경로를 바꿀 때는
`index.html`이 아니라 `routes.json`만 갈아끼우면** 모든 기기에 반영됩니다.

지역별 시나리오 수: 강남 15개, 판교 4개, 시흥 10개.

### 섹터 (자유주행 구역)
정해진 코스를 따라가는 대신 지정된 구역 안을 자유롭게 훑는 방식입니다.
시나리오 칩에 **▣** 표시가 붙은 것이 구역입니다.

- 구역 경계를 점선 다각형으로 표시
- 구역 내 주행 가능 도로를 파란 선으로 표시 (강남 11개 구역은 HD맵 기준 데이터 내장)
- 경로 API를 호출하지 않음 — 턴바이턴 안내 없음
- 주행하면 지나온 길이 초록색으로 칠해짐
- 구역을 벗어나면 음성·화면 경고
- ⏸ 정지 시 실제 주행 거리(km)가 주행 기록에 남음

강남 구역 도로는 표준노드링크(HD맵) 기반이라 `LINK_ID`·도로명·차선 수가 함께 들어 있습니다.
구역에 도로가 저장돼 있지 않으면 `hd_roads.json`에서 구역 경계로 잘라 채웁니다
(현재 HD맵 원본은 강남만 포함).

**구역 내 길 표시 방식** — 역삼동 구역만 도로가 644개라 전부 그리면 확대·축소가 끊깁니다.
화면에 걸치는 것만 그리고, 지도 이동이 끝난 뒤 다시 계산합니다.

| 배율 | 표시 | 굵기 |
|------|------|------|
| 13 이하 | 구역 경계만 (안내문 표시) | — |
| 14 | 큰길 위주 최대 350개 | 4 / 3 |
| 15 이상 | 최대 700개 (사실상 전부) | 5~8 / 3.75~6 |

- 색은 보라(`#7c3aed`)입니다. 경로선(파랑)·지도 기본 도로와 겹치지 않게 골랐습니다.
- 차선 수 2개 이상은 굵고 진하게(투명도 0.95), 1차선 골목은 조금 얇게(0.80) 그립니다.
- 확대할수록 굵어집니다. 축소 상태에서 뭉개지지 않으면서 확대하면 또렷해집니다.
- 상한에 걸리면 **차선 수가 많은 도로부터** 그립니다. 앞에서부터 자르면 골목만 남고
  큰길이 빠져 도로망이 끊겨 보이기 때문입니다.
- 구역 채움은 옅게(0.05) 두어 길이 묻히지 않게 했습니다.

기기가 버거우면 `sectorRoadMaxDraw()` 값을 낮추거나, 설정 메뉴의
**🛣 구역 내 길 표시**를 끄면 됩니다.

### 경로 수정
설정 메뉴 → **✏️ 경로 수정**. 주행 중에는 열리지 않습니다(⏸ 먼저).

Ver.1은 마커를 드래그하는 방식이었지만, TMAP v2 마커 드래그는 모바일에서 동작이
일정하지 않아 **탭 방식**으로 바꿨습니다. 태블릿에서 더 정확합니다.

| 조작 | 동작 |
|------|------|
| 지도 탭 | 그 지점에 경유점 추가 (가장 가까운 구간 사이에 자동으로 끼워 넣음) |
| 경유점 탭 | 해당 경유점 삭제 |
| 🟢 출발지 옮기기 → 지도 탭 | 출발 핀 이동 |
| 🔴 도착지 옮기기 → 지도 탭 | 도착 핀 이동 |
| ↩ 되돌리기 | 직전 조작 취소 (30단계) |
| 💾 저장 | 확정 · 취소하면 원래 경로로 복구 |

- 탭할 때마다 경로를 다시 그려 결과를 바로 확인할 수 있습니다.
- 편집 중에는 자동 경유점 필터를 적용하지 않습니다. 직접 찍은 지점은 그대로 반영됩니다.
- 경유점이 5개를 넘으면 경고가 뜹니다 (TMAP API 한도).
- 저장하면 **도착지를 옮긴 경우 다음 구간 출발지**, **출발지를 옮긴 경우 이전 구간
  도착지**가 함께 따라와 구간이 끊기지 않습니다.
- 수정 내용은 이 기기의 `localStorage`에 남습니다. **↺ 경로 수정 되돌리기**로 초기화합니다.

### 경로 내보내기
설정 메뉴 → **🗺 경로 내보내기**. 현재 시나리오·구간·경유점·구역을 `routes.json`
형식으로 저장합니다. 저장소 루트에 덮어쓰고 push하면 모든 기기에 반영됩니다.

내보낸 파일을 다시 읽어 들여 시나리오 목록·구간 수·섹터·구역 도로가 그대로
복원되는지 왕복 검증했습니다.

## 아직 옮기지 않은 Ver.1/Ver.2 기능

시나리오 편집·구간 추가·삭제, 섹터 그리기(관리자용 ▣ 추가), 패널 리사이즈,
교통정보 오버레이, 네이버 지도 열기, 밝은 화면 모드, 수집 시스템 연동.

## 프로젝트 구조

```
nav-app/
├── index.html       # 전체 앱 (화면·지도·GPS·경로 안내·구역·기록)
├── routes.json      # 경로 원본 — 구간·경유점·구역 (Ver.2에서 가져옴)
├── hd_roads.json    # HD맵 도로 원본 — 구역에 도로가 없을 때만 사용
├── manifest.json    # PWA 설정
├── sw.js            # 앱 셸 캐시 (TMAP 응답 제외, 데이터 파일은 네트워크 우선)
├── README.md
└── icons/
```
